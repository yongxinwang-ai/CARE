# Implementation of Elite Sampling for GRPO in EasyR1

## My proposal

3.1 The Hard Version ("Literal Golden Sample Update")
- For each prompt, generate GG rollouts; select the single best (golden) sample by reward.
- Update the policy using only this trajectory (batch size = 1 per prompt).
- This maximizes exploitation, but is likely unstable due to extreme gradient variance.
3.2 The Soft Version (Elite-Biased Sampling)
- For each prompt, generate GG rollouts.
- Select the top-k (by reward), or all rollouts with positive reward.
- Update the policy using only these elite samples, possibly weighing by reward or using Cross-Entropy Method (CEM)-style updates.
3.3 Structured Version: Novel Golden Sample-Based Group Updates
3.3.1 Perturbed Golden Ensemble (PGE) Update
Overview:
 Instead of using a group of independent rollouts or truncating a master trajectory, the Perturbed Golden Ensemble strategy forms a training batch by generating multiple locally perturbed variants of a single, high-reward golden sample.
Procedure:
1. Golden Sample Selection:
 For each training prompt, sample a group of G candidate rollouts using the current policy. Select the trajectory with the highest reward as the golden sample.
2. Local Perturbation:
 Generate N variants of the golden sample by applying lightweight, targeted perturbations.
 Possible perturbation methods include:
  - Randomly substituting, deleting, or inserting tokens at selected positions (especially in the reasoning steps/CoT);
  - Replacing certain steps in the chain-of-thought with alternative completions generated by the model (e.g., top-k sampling or temperature sampling for a single token/step);
  - Injecting small amounts of noise or stochasticity at specific locations without re-generating the entire sequence.
3. Batch Construction:
 Assemble a batch consisting of the golden sample and its N perturbed variants (N+1 total rollouts).
4. Reward Re-evaluation:
 Each member of the batch is evaluated by the verifier for reward. This ensures that only valid perturbations contribute positively to learning.
5. Group-Based Advantage Computation:
 Compute normalized, group-relative advantages for the batch, using the same whitening procedure as standard GRPO (subtract mean and divide by standard deviation within the batch).
6. Policy Update:
 Perform a policy update using the full perturbed batch. This design allows the learning signal to focus on the region around the golden sample, but maintains stability through batch averaging and local exploration.

---
3.3.2 Contrastive Golden Sample Group (CGSG) Update
Overview:
 This approach frames the update as a contrastive learning problem: the golden sample acts as a positive anchor, and the rest of the batch is constructed from rollouts with the lowest rewards (hard negatives). 
The objective is to simultaneously reinforce the probability of the golden sample and explicitly demote the worst-performing alternatives, encouraging the model to sharpen its distinction between correct and incorrect reasoning.
Procedure:
1. Golden Sample Selection:
 As before, generate G rollouts per prompt, and select the highest-reward trajectory as the golden sample.
2. Hard Negative Selection:
 Identify one or more rollouts from the same group with the lowest reward(s) to serve as hard negatives. Optionally, negatives may be chosen based on reward, diversity (maximally different from the golden sample), or a combination.
3. Batch Construction:
 Construct a training batch for the update consisting of the golden sample and the selected hard negatives.
4. Contrastive and Policy Losses:
 The update objective can be formulated as:
  - Contrastive Loss: Maximize the log-probability (or advantage) of the golden sample while minimizing that of the negatives:
  $$\mathcal{L}_\text{contrast} = -\log \frac{\exp(A_\text{golden})}{\exp(A_\text{golden}) + \sum_j \exp(A_{\text{neg},j})}$$
  - where A is the advantage of sample x.
  - (Optional) Policy Gradient: Augment the contrastive loss with standard policy gradient or advantage-based loss to further encourage exploration.
5. Group Advantage (Optional):
 Alternatively, the batch can use normalized group-based advantages: the golden sample receives the highest positive advantage, while negatives receive negative advantages.
6. Policy Update:
 Update the policy using the combined loss, directly encouraging the model to prefer the golden sample and disfavor the negatives.

---
3.4 Baselines
- Standard GRPO (group-based, no elite or golden sample bias).
- (Optional) PPO with a critic (for reference).
- (Optional) Curriculum learning without elite sampling.

### Phase 2: Perturbed Golden Ensemble (PGE) Implementation

This phase implements the core logic for the PGE update rule. The main changes will be within the rollout worker, which is responsible for generating the training batches.

**Sub-task 2.1: Modify the Rollout Worker**

  * **File to Modify:** `verl/workers/ppo_worker.py` (or equivalent GRPO worker file).

  * **Action:** Adapt the `rollout` or `sample` method in the worker to implement the PGE procedure when `trainer.grpo.variant == 'pge'`.

  * **Detailed Logic Flow:**

    1.  **Read Config:** The worker's `__init__` method should take the `pge_config` as an argument.
    2.  **Conditional Execution:** Inside the main data generation loop, check if `pge_config.enabled` is true.
    3.  **Golden Sample Selection (if PGE enabled):**
          * Generate `G` candidate rollouts for a given prompt using the current policy (as in standard GRPO). Let's call this the *candidate group*.
          * Evaluate each of the `G` rollouts using the reward function/verifier.
          * Identify the trajectory with the highest reward. This is the **golden sample**.
    4.  **Perturbation & Batch Construction:**
          * Import the new functions from `verl/utils/perturbations.py`.
          * Keep the original golden sample.
          * Loop `pge_config.num_perturbations` times:
              * Create a copy of the golden sample's token sequence.
              * Apply one or more of the configured perturbation methods from the utils module.
              * This creates a **perturbed variant**.
          * The final training batch for this prompt consists of: `[golden_sample] + N_perturbed_variants`.
    5.  **Reward Re-evaluation:**
          * As per the proposal, each of the `N+1` samples in the newly constructed batch must be evaluated by the verifier to get its final reward.
    6.  **Return Structured Batch:** The worker should return this structured batch (samples and their final rewards) to the main trainer.

**Sub-task 2.2: Integrate PGE Batch into the Trainer**

  * **File to Modify:** `verl/trainer/ray_trainer.py` (or the file containing the GRPO loss calculation).
  * **Action:** Ensure the trainer correctly processes the PGE batch.
  * **Details:** This should be straightforward. Since the PGE batch is pre-structured with valid rewards for each sample, the existing GRPO advantage computation logic (whitening: subtract mean, divide by std dev) can be applied directly to this batch. No new loss function is needed for PGE; the innovation is purely in the batch construction.

### Phase 3: Contrastive Golden Sample Group (CGSG) Implementation

This phase focuses on creating the contrastive learning dynamic between the best and worst samples.

**Sub-task 3.1: Modify the Rollout Worker for CGSG**

  * **File to Modify:** `verl/workers/ppo_worker.py` (or equivalent).

  * **Action:** Add logic to the `rollout` method to construct a contrastive batch when `trainer.grpo.variant == 'cgsg'`.

  * **Detailed Logic Flow:**

    1.  **Read Config:** The worker's `__init__` method should take the `cgsg_config` as an argument.
    2.  **Conditional Execution:** Add an `elif` condition to the data generation loop for `cgsg_config.enabled`.
    3.  **Sample Selection (if CGSG enabled):**
          * Generate `G` candidate rollouts and evaluate them with the reward function.
          * Select the single trajectory with the **highest** reward as the **golden sample** (the positive).
          * Select `cgsg_config.num_negatives` trajectories with the **lowest** rewards as the **hard negatives**.
    4.  **Batch Construction:** The training batch is simply `[golden_sample] + hard_negatives`.
    5.  **Return Contrastive Batch:** The worker returns this batch and their corresponding rewards to the trainer.

**Sub-task 3.2: Implement the CGSG Loss Function in the Trainer**

  * **File to Modify:** `verl/trainer/ray_trainer.py`.

  * **Action:** This is the most critical part of CGSG. The training step must be modified to compute the new loss.

  * **Detailed Logic Flow:**

    1.  **Conditional Loss Calculation:** In the `training_step` or `compute_loss` method, add a condition for `cfg.trainer.grpo.cgsg_config.loss_type`.
    2.  **Option A: "normalized\_advantage" (Easier):**
          * If this option is selected, reuse the standard GRPO update mechanism.
          * The group advantages will be computed over the small `[golden] + [negatives]` batch.
          * By design, the golden sample will receive a high positive advantage, and the negatives will receive large negative advantages, achieving the contrastive goal implicitly. This is a good first implementation.
    3.  **Option B: "contrastive\_loss" (As per Proposal):**
          * If this option is selected, a new loss function must be implemented.
          * For each batch, calculate the advantages `A` for all samples (the golden and the negatives).
          * Implement the contrastive loss formula:
            $$\mathcal{L}_\text{contrast} = -\log \frac{\exp(A_\text{golden})}{\exp(A_\text{golden}) + \sum_{j=1}^{N_{\text{neg}}} \exp(A_{\text{neg},j})}$$
          * The total loss for the update step will be this $\\mathcal{L}\_\\text{contrast}$. The policy will be updated to minimize this loss, effectively maximizing the relative probability of the golden sample.
